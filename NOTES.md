# NOTES — журнал решений и известные проблемы данных

## Журнал решений

- Этап 0 (первая версия ТЗ): Python 3.11, виртуальное окружение `.venv`, зависимости в `requirements.txt`; CLI на `argparse`.
- Исходные файлы `N_C_.xls`, `TANMB_.xls`, `Расчет.xlsx` лежат в `data/raw/` и хранятся в git (они небольшие, нужны тестам).
- Этап 1:
  - Если в книге найден экспорт прибора (лист с заголовком `Size` + `M####` и блоками метаданных), остальные листы этой книги не читаются — это ручные расчёты (`Лист1`, `Лист2`, `Во!`).
  - Метки метаданных ищутся по нормализованному тексту (без пробелов, `*`, точки на конце); значение — первое подходящее справа в той же строке (в `TANMB_.xls` оно может быть через 4–5 ячеек).
  - Таблица перцентилей из блока метаданных сохраняется в `meta["percentiles"]`, D[4,3] прибора — в `meta["d43_instrument"]` (для сверки).
  - Окно «> X мкм» считается как 100 − ΣQ(X): если кривая не доходит до 100 %, недостающее относится к крупным частицам. Перенормировки нет.
  - Повторы усредняются только внутри одного файла, при одинаковом названии и одинаковой сетке. Метаданные (обскурация, Error и т.п.) — среднее, флаги повторов переносятся в среднее.
  - Расхождение повторов N/C: ≤ 0,8 п.п. (проверено тестом).
  - CSV: при `;` или табуляции — десятичная запятая; при `,` — десятичная точка; таблица через пробелы с числами вида `1,5` тоже распознаётся.
  - В `Расчет.xlsx` столбец `tt` — доли по интервалам (сумма ≈ 100); он отбрасывается, т.к. есть накопленный `FreqCum`.
  - Добавлена команда `python -m psd_lab metrics data/raw` — таблица метрик и флагов в консоли.
- Этап 2:
  - Столбики Q, % строятся по интервалам от 0 с шагом сетки (или `--bin`) интерполяцией накопленной кривой; при ширине, кратной шагу, это точные разности исходных точек. Сумма столбиков = последнее значение кривой (перенормировки нет, проверено тестом).
  - Шаг сетки — медиана разностей размеров (первые нерегулярные точки 0,1 мкм попадают в первый столбик).
  - Подписи осей курсивом через `fontstyle="italic"`, а не mathtext: mathtext плохо дружит с кириллицей при `--lang ru`.
  - Предел X — d99, округлённый вверх до ряда 1; 1,2; 1,5; 2; 2,5; 3; 4; 5; 6; 8 × 10ⁿ. Поэтому кривая у правого края ≈ 99 %, а не ровно 100 %.
  - Рамка с названием — в правом верхнем углу, но чуть ниже верха (на 80 % высоты), чтобы не налезать на кривую у 100 %.
  - Картинки: `out/<имя файла>/<образец>.png` (символы `/ \ : * ? " < > |` заменяются на `_`, т.е. `N/C` → `N_C.png`) + `out/compare.png`.
  - Сравнительный график: цвет — номер образца внутри файла (фиксированная палитра из 8 цветов), тип линии — файл (сплошная/штрих/точки). Так 12 кривых различимы и в ч/б.
  - В Windows маски вида `data/raw/*.xls` раскрываются самой программой.
- **Переход на новое ТЗ (PSD-Lab):**
  - Пакет переименован в `psd_lab`; ядро — `psd_lab/core` (не зависит от GUI), окна — `psd_lab/gui`. Старые команды `metrics`/`plot` заменены режимом `--batch`.
  - Python 3.12 (`.venv` пересоздан), добавлены Pillow и PyInstaller. В облачной среде разработки для Tk установлен пакет `python3-tk`; в Windows Tk входит в стандартный Python.
  - Флаг ИНФО «разный TradeOff»: max/min по измерениям одного файла > 5. В `N_C_.xls` — 41 раз (1862…75858), флаг стоит у всех 8 измерений; в `TANMB_.xls` — 4,9 раза, флага нет.
  - Уровни флагов хранятся кодами ERROR/WARN/INFO, пользователю показываются как ОШИБКА/ВНИМАНИЕ/ИНФО.
  - Графики рисуются функциями `draw_sample`/`draw_compare` на переданной фигуре — один код и для экрана, и для экспорта. Без `pyplot` (нет глобального состояния, безопасно в GUI).
  - Отчёт `report.html`: картинки встроены base64 при 110 dpi (файл ≈ 1 МБ); одинаковые флаги разных образцов (TradeOff файла) показываются одной строкой.
  - `summary.xlsx`, лист «Кривые»: на каждый образец 3 столбца (размер, ΣQ, Q) + пустой разделитель, т.к. сетки у файлов разные. Q — разность соседних точек ΣQ.
  - Подписи осей на экспортных графиках по умолчанию английские (как на образце), русские — в настройках или `--lang ru`.
  - Настройки — `settings.json` в папке данных `PSD-Lab-data` (рядом с exe; при запуске из исходников — в корне проекта; если нельзя писать — `%APPDATA%\PSD-Lab`).

- **Этап 3 (окно программы):**
  - Основа — ttk-тема `classic`, перекрашенная под палитру Win95 (`gui/theme.py`); флажки и переключатели в диалогах — классические `tk.Checkbutton`/`tk.Radiobutton` (в Windows они рисуются как в Win95).
  - Рамка у кнопок только у кнопки по умолчанию (OK) — как в Win95; у остальных её нет.
  - Флажки в дереве образцов: в Tk 8.6 у Treeview нет флажков, поэтому у каждой строки картинка «флажок + иконка флага качества», собранная из двух иконок 16×16. Клик по картинке или пробел — включить/выключить; клик по файлу — все его образцы.
  - Переименование (F2) меняет имя у исходных измерений образца, поэтому усреднение повторов после переименования сохраняется.
  - Перетаскивание файлов на окно **не сделано**: в стандартном Tk нет drag&drop без внешнего расширения tkdnd (его пришлось бы таскать в exe). Открытие — через меню, тулбар, Ctrl+O и «Последние файлы».
  - Кнопка «Копировать в буфер» у графика работает только в Windows (через WinAPI, формат CF_DIB). В других ОС — сообщение «используйте Сохранить PNG».
  - Кнопка «Справка» на тулбаре и F1 пока открывают «О программе»; полноценная справка — README на этапе 8.
  - Иконки рисует `tools/make_icons.py` примитивами Pillow без сглаживания в 16 цветах Windows; 32×32 — увеличение ×2 (для экранов ≥ 175 %). Образец всех иконок — `tools/icons_preview.png`.
  - `--selftest`: загрузка `data/raw`, по скриншоту на каждую вкладку и на диалоги «Настройки» и «О программе», плюс заставка → `out/screens/`. Пользовательские настройки при этом не читаются и не сохраняются.
  - Скриншоты в облачной среде разработки сделаны в Linux (Xvfb, шрифт DejaVu Sans вместо MS Sans Serif), в Windows шрифт будет мельче и «острее». Окончательная сверка вида — на этапе 4 по `--selftest` собранного exe.
- **Этап 4 (сборка exe):**
  - `build_exe.bat` → `tools/build_exe.py`: PyInstaller, one-folder, `--windowed`, иконка `assets/app.ico`, версия и описание в свойствах exe (VSVersionInfo, русская локаль), `assets/` внутри сборки, `matplotlib.backends.backend_tkagg` и модули scipy — как hidden imports. Точка входа — `tools/launcher.py` (у `psd_lab/__main__.py` относительные импорты).
  - Рядом с exe кладётся папка `examples` (копия `data/raw`): по ней работает `--selftest` собранной программы, и пользователю есть на чём попробовать.
  - Проверка: копия программы в `build/Проверка кириллицы и пробелов/PSD-Lab` и запуск оттуда `--selftest`; архив создаётся только если самопроверка прошла. Скриншоты собранной программы — `out/screens_exe`.
  - pandas исключён из сборки (в коде не используется, −22 МБ); в `requirements.txt` остаётся по ТЗ.
  - У exe без консоли нет вывода на экран, поэтому `--selftest` пишет `out/screens/selftest.txt`, а `--batch` — `batch_log.txt` в папку результатов.
  - PyInstaller не умеет собирать exe для Windows из Linux. В облачной среде весь сценарий сборки прогнан под Linux (одна папка ≈ 190 МБ, zip ≈ 100 МБ): собранная программа запускается из пути с кириллицей и пробелами, `--selftest` и `--batch` проходят. Сам `PSD-Lab.exe` собирается у пользователя на Windows через `build_exe.bat`.
  - Первая попытка сборки у пользователя: Python 3.12 не установлен (есть только новый установщик `py`, сообщение «No runtime installed that matches 3.12»), а bat пошёл дальше и упал на отсутствующем `.venv`. Исправлено: bat ищет Python 3.11+ (`py -3.12/-3.13/-3.11/-3.14/-3`, затем `python`), проверяет, что `.venv\Scripts\python.exe` действительно создан; если Python нет — сам запускает `py install 3.12`; недоделанный `.venv` удаляется.
  - `.gitattributes`: `*.bat` хранится с переводами строк CRLF (иначе cmd.exe может неверно читать файл); `build_exe.bat` в UTF-8 с `chcp 65001`, чтобы русские сообщения отображались.
- **Доработка интерфейса после первой сборки (отзыв: «на 27″ кнопки очень маленькие»):**
  - Масштаб = DPI Windows × масштаб пользователя. «Авто» по логическому размеру экрана: ≥ 2400×1350 → 125 %, ≥ 3400×1900 → 150 %, иначе 100 % (27″ 2560×1440 при 100 % → 125 %; 4K при 150 % → 150 × 1,25 ≈ 188 %). Ручной выбор 100–200 % — «Вид → Масштаб интерфейса» и в настройках, применяется после перезапуска (программа предлагает перезапуститься сама).
  - Все отступы считаются через `theme.px()`; шрифты в пунктах масштабируются через `tk scaling`.
  - Шрифт: «Microsoft Sans Serif» (векторный двойник MS Sans Serif, тот же рисунок) вместо растрового MS Sans Serif, который в Windows 10/11 при увеличении рассыпается. Запасные: Tahoma, MS Sans Serif, Arial. Отступление от ТЗ ради читаемости.
  - Иконки увеличиваются только в целое число раз (16 → 32 → 48 → 64, ближайший сосед) — пиксель-арт остаётся чётким. Большой тулбар: иконки 32–64 px с подписями под ними (как в лабораторном софте конца 90-х); подписи отключаются («Вид → Подписи под кнопками»).
  - Графики на экране: matplotlib сам умножает dpi на масштаб Tk («device pixel ratio»), поэтому у экранной фигуры dpi 96, а размер фигуры подгоняется под холст перед каждой отрисовкой. `tight_layout()` в функциях рисования выключает движок компоновки — в панели графика он включается обратно, чтобы график перекомпоновывался при изменении размера окна.
  - Под графиком — панель «Результаты» (d10, d50, d90, span, D[4,3], D[3,2], доли по окнам, обскурация) в белых вдавленных полях, как на панели прибора; обскурация вне окна 0–40 % — красным.
  - «Свойства» — таблица «параметр — значение» с разделами (Образец / Прибор / Результат); флаги — отдельная панель «Замечания по качеству» с переносом строк.
  - Стартовая страница вместо пустого графика: «Открыть файлы / папку / примеры» и список последних файлов. Кнопка и пункт меню «Открыть примеры» (папка `examples` рядом с exe или `data/raw`).
  - В сводке — значки флагов в первой колонке, числа с десятичной запятой.
  - Окно: на первом запуске разворачивается на весь экран; размер, положение и открытые файлы запоминаются и открываются при следующем запуске (отключаемо в настройках).
  - Проверено скриншотами `--selftest` в трёх режимах: 1920×1080 при 100 %, 2560×1440 (авто 125 %), 3840×2160 при Windows 150 % (итого ≈ 188 %). Для эмуляции DPI есть переменные окружения `PSD_LAB_DPI_SCALE` и `PSD_LAB_UI_SCALE`.
  - По скриншоту пользователя (Windows, 2560×1440): добавлен масштаб 110 %; иконки тулбара и кнопок графика перерисованы в настоящем 32×32 (контур, блик, тень, 16 цветов) вместо увеличения 16×16; размеры, кратные 32, берутся из них. Найдена ошибка: один и тот же файл, открытый из двух папок (`data\raw` и `examples`), попадал в дерево дважды — теперь повторы узнаются по SHA-1 содержимого.

## Данные и подводные камни

### Физический смысл
Данные — **лазерная дифракция, Fritsch ANALYSETTE 22 MicroTec plus** (расчёт по Фраунгоферу, 102 канала, 0,08–2000 мкм).

Кривая `FreqCum` — **накопленная объёмная доля, %, частиц мельче указанного размера** (Size = верхняя граница интервала). Проверено: D[4,3] из кривой по серединам интервалов совпадает с приборным до 0,1 мкм.

Обозначения:
- **Q, %** — доля в интервале (столбики);
- **ΣQ, %** — накопленная (кривая).

В исходном Excel-шаблоне и картинке-образце подписи **перепутаны** — не повторять.

Материал по названию: TANMB = Ti–Al–Nb–Mo–B (γ-TiAl типа TNM-B1) с добавками Si, C, Y₂O₃ в двух состояниях «N/C» и «П/С». Смысл обозначений неизвестен; спросить пользователя на этапе 6, не раньше.

### Экспорт Fritsch (`N_C_.xls`, `TANMB_.xls`)
- Лист `Sheet`. Строка-заголовок (≈ 6-я в Excel): `Size`, `FreqCum`, `VarCoeff`, затем столбцы `M4246`, `M4322`… — это **измерения**.
- Ниже — числовые строки. Size = 0.1, 1, 2 … 200 (`N_C_.xls`, шаг 1 мкм) или 0.1, 2, 4 … 500 (`TANMB_.xls`, шаг 2 мкм). Сетку не предполагать.
- **`FreqCum`/`VarCoeff` рядом с Size = среднее и CV по ВСЕМ измерениям файла (то есть по разным материалам) — игнорировать.**
- Ниже данных — **блоки метаданных** на каждое измерение. Метки на немецком (`N_C_.xls`) или английском (`TANMB_.xls`). Значение правее метки в той же строке, **не обязательно в соседней ячейке** (в строке несколько пар «метка — значение»). Метки:
  - `Mess-Nr.` / `Meas.Nr` → номер (сопоставить с `M####`);
  - `Material` → название (`N/C+si`, `П/С +0,5Y2O3`);
  - `Datum` / `Date`;
  - `Berechnung` / `Calculation` → модель;
  - `TradeOff` → регуляризация (автоподбор);
  - `Strahlabsorption` / `Beam Obscuration` → обскурация, %;
  - `Error *` / `Error` → ошибка подгонки (единицы не указаны; сноска «Error muss kleiner als 20% sein!»);
  - `Ultraschallintensität` / `Ultrasonics`, `Pumpengeschwindigkeit` / `Pump`, `Messbereich` / `Meas. Range`;
  - `Mode`, `Span`, `D[4,3]`, таблица перцентилей.
- Листы `Лист1`, `Лист2`, `Во!` в `N_C_.xls` — ручные расчёты (с ошибками), **не экспорт**. Критерий настоящего экспорта — у измерений есть блоки метаданных.
- Встроенные картинки прибора игнорировать.

### `Расчет.xlsx`
Старый шаблон (создан 2017, сохранён 2019, к серии 2020 не относится, материал неизвестен). Листы `6ч`, `8ч`, `10ч`: каждый лист — образец. Столбец A — размер (1…100 мкм), B — `FreqCum`. Остальные столбцы производные и **с ошибками** — брать только A и B. Время в названии листа (6/8/10 ч) — вход для модуля «Кинетика помола».

### Ошибки, которые НЕЛЬЗЯ повторять
1. Сдвиг на строку между размером и значением (в старых листах ΣQ «при 5 мкм» взят при 3–4 мкм).
2. Ручные поправки (в `Лист2` есть `=B4-0,7`).
3. **Обрезка кривой и перенормировка до 100 %.** Образец-картинка — это N/C (M4246), обрезанная на 40 мкм и перенормированная; реально ниже 40 мкм только 78,4 %.
4. Перепутанные подписи Q / ΣQ.

### Флаги качества
| Условие | Уровень | Текст для пользователя |
|---|---|---|
| Обскурация < 0 (M4251 −53, M4253 −51, M4322 −37 — все с Si) | ОШИБКА | фон записан неверно, результат ненадёжен |
| Обскурация > 40 % (M4347 = 64) | ВНИМАНИЕ | риск многократного рассеяния |
| \|последняя точка − 100\| > 0,6 | ВНИМАНИЕ | кривая не доходит до 100 % |
| Кривая не монотонна | ОШИБКА | |
| Повторы расходятся > 2 п.п. в любой точке (у N/C ≤ 0,8) | ВНИМАНИЕ | |
| TradeOff у образцов одного файла отличается > 5 раз | ИНФО | степень сглаживания разная, форму пиков сравнивать осторожно |
| Error | без флага | только показывать значение |
